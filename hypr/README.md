# Hyprland config

This directory configures [Hyprland](https://hypr.land) on this machine. As of
Hyprland **0.55** the config format is **Lua** (the old `hyprlang` `.conf` format
is deprecated and will be removed in a future release).

## Files

| File | Purpose |
| --- | --- |
| `hyprland.lua` | **The active config.** Hyprland loads this on startup and on `hyprctl reload`. When both `hyprland.lua` and `hyprland.conf` exist, the `.lua` file wins. |
| `hyprland.conf.bak` | Backup of the original hyprlang config, kept as a reference/fallback. Not loaded. |
| `hyprmon.lua` | **Monitor layout**, generated by HyprMon and `require`d at the end of `hyprland.lua`. This is the only place per-monitor rules live; `hyprland.lua` just has a catch-all `preferred, auto` rule for unknown outputs. |
| `hypridle.conf` | Idle daemon: dim at 4 min, lock at 5, screen off at 6, suspend at 15. |
| `hyprlock.conf` | Lock-screen (hyprlock) config. `hyprlock` is a **separate program** from the compositor and still uses the hyprlang `.conf` format — it is **not** affected by the Lua migration and should stay as-is. (The same applies to other ecosystem tools like `hypridle`/`hyprpaper`.) |

To restore the old config:

```sh
mv hyprland.conf.bak hyprland.conf && rm hyprland.lua && hyprctl reload
```

## How the Lua config works

Everything is driven by Hyprland's `hl.*` API. The main functions used here:

| Function | What it does |
| --- | --- |
| `hl.config({ ... })` | Sets grouped variables (`general`, `decoration`, `input`, `misc`, layouts, …). |
| `hl.monitor({ ... })` | Declares a monitor (output, mode, position, scale). |
| `hl.bind("MOD + KEY", dispatcher, opts?)` | A keybinding. The dispatcher comes from the `hl.dsp.*` namespace. |
| `hl.on("hyprland.start", fn)` | Runs `fn` once at startup — this replaces `exec-once`. |
| `hl.curve(...)` / `hl.animation(...)` | Animation bezier curves and per-element animations. |
| `hl.gesture(...)` / `hl.device(...)` | Touchpad gestures and per-device input settings. |
| `hl.window_rule({ match = {...}, ... })` | Per-window rules (replaces `windowrule`). |
| `hl.exec_cmd(cmd)` / `hl.env(k, v)` | Run a shell command / set an environment variable. |

### Key translation from the old format

| Old hyprlang | New Lua |
| --- | --- |
| `exec-once = foo` | inside `hl.on("hyprland.start", function() hl.exec_cmd("foo") end)` |
| `monitor=eDP-1,1920x1200,0x0,1` | `hl.monitor({ output="eDP-1", mode="1920x1200", position="0x0", scale=1 })` |
| `bind = $mainMod, Q, killactive` | `hl.bind(mainMod .. " + Q", hl.dsp.window.close())` |
| `bind = $mainMod, F, fullscreen, 0` | `hl.dsp.window.fullscreen({ mode = "fullscreen" })` |
| `bind = $mainMod, D, fullscreen, 1` | `hl.dsp.window.fullscreen({ mode = "maximized" })` |
| `movetoworkspacesilent, N` | `hl.dsp.window.move({ workspace = N, follow = false })` |
| `bindel`/`bindl`/`bindm` flags | the 3rd arg table: `{ locked = true, repeating = true }` / `{ mouse = true }` |
| `$mainMod = SUPER` | `local mainMod = "SUPER"` |
| `windowrule = match:title X, float true` | `hl.window_rule({ match = { title = "X" }, float = true })` |

Bind modifiers/keys are written as a single string joined with ` + `,
e.g. `mainMod .. " + SHIFT + 1"`.

### Pywal (wallust/wal) colour theming

The old config did `source = ~/.cache/wal/colors-hyprland.conf` to pull pywal's
generated palette. That source file is hyprlang and **cannot** be `require`d from
Lua, so the colours are loaded a different way:

```lua
local function wal_colors() ... end   -- reads ~/.cache/wal/colors (16 hex lines)
local wal = wal_colors()
local function color(n) return wal[n+1] or "rgb(595959)" end
```

`~/.cache/wal/colors` is pywal's plain output: one `#rrggbb` per line, in order
`color0 … color15`. The helper reads it at config-load time and exposes:

- `color(0)` … `color(15)` — palette entries as `rgb(rrggbb)` strings
- `background` — alias for `color(0)`

These feed the window borders:

```lua
col = {
    active_border   = { colors = { color(1), color(10) }, angle = 90 },  -- gradient
    inactive_border = background,
},
```

Because the palette is read every time Hyprland (re)loads, re-running `wal`/your
theming tool and then `hyprctl reload` re-applies the new colours automatically —
no template editing required. If `~/.cache/wal/colors` is missing, borders fall
back to a neutral grey.

> Note: Lua configs run with the **full Lua standard library** (`io`, `os`, …) and
> can execute arbitrary code. That's what makes reading the colour file possible,
> but it also means you should only run config you trust.

### Media / laptop keys
Volume, mute, mic-mute and brightness keys work on the lock screen (`locked`) and
repeat when held; they show the Quickshell OSD. Play/Pause goes through
Quickshell (nothing loaded in Cider: shuffles the Heavy Rotation mix) and falls
back to `playerctl`.

## Notifications

Quickshell is the notification daemon (toasts + notification centre on the bell).
`dunst.service` is masked so D-Bus doesn't start dunst instead. Colours follow
pywal automatically.

## Autostart

Launched once at startup via `hl.on("hyprland.start", ...)`:

- `hyprlock` — lock screen
- `awww-daemon` — wallpaper daemon
- `qs -n -d` — Quickshell: bar, notifications, OSD, launcher, sidebars (config in `~/.config/quickshell`)
- `polkit-kde-authentication-agent-1` — GUI password prompts for privileged actions
- `hypridle` — idle lock / screen-off / suspend

## Editing tips

- Validate syntax before reloading: `luajit -e 'assert(loadfile("hyprland.lua"))'`
- Apply changes to a running session: `hyprctl reload`
- A bad reload keeps the previously-loaded config in memory, so a syntax error
  won't crash your session — fix the file and reload again.
- You can split this into multiple files and pull them in with `require("name")`
  (relative to this directory, no `.lua` extension). Each `require` is its own
  scope, so an error in one file doesn't stop the others.
